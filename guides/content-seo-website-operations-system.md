# Content, SEO, and website operations system

## Purpose

This guide defines how to manage content quality, metadata, search visibility basics, and ongoing website operations after implementation.

## What this system covers

- page planning and content structure
- metadata and on-page SEO basics
- publishing and update workflows
- analytics and conversion checks
- QA for content-heavy websites

## Core principle

A website is not healthy just because it renders. It also needs:

- clear page purpose
- usable content structure
- correct metadata
- working forms and conversion paths
- repeatable update operations

## Suggested lifecycle

### 1. Page and content planning
Define page purpose, audience, keyword/topic intent, CTA, and required assets.

### 2. Content assembly
Collect approved copy, headings, images, and structured blocks.

### 3. Metadata and on-page SEO
Verify titles, descriptions, headings, URLs, internal links, indexing, and social previews.

### 4. Publishing workflow
Define who can publish, what must be reviewed, and how updates are tracked.

### 5. QA and analytics
Verify form paths, event tracking, CTA behavior, and content rendering across devices.

### 6. Ongoing operations
Track updates, stale content, broken links, and recurring improvement opportunities.

## Guardrails

- do not publish unreviewed placeholder metadata
- do not treat SEO as only a title tag problem
- tie content changes to page goals and user paths
- keep publishing responsibility clear
