## How to use

1. Start with the core operating guide and general skills.
2. Add the stack pack that matches the project.
3. Add project-specific rules only where the stack pack is still too broad.
4. Combine packs when the system spans app, backend, database, deployment, and testing layers.

## Notes

These are starter packs for v1.

If your project uses a different stack, add a new pack with:

- assumptions
- common workflows
- build/test/verify commands
- security pitfalls
- performance pitfalls
- file/layout conventions
