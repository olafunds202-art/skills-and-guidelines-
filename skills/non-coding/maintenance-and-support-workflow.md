# Skill: Maintenance and Support Workflow

## Purpose

Use this skill after launch when a project enters a support, maintenance, or iteration phase.

## Good use cases

- retained client websites
- automation support
- bugfix windows
- minor content or settings changes
- post-launch monitoring and upkeep

## Workflow

1. Define what support includes.
2. Define what is considered incident, bug, maintenance, or enhancement work.
3. Define intake and triage for new requests.
4. Define response expectations and priorities.
5. Define release or deployment rules for maintenance changes.
6. Keep a maintenance log or runbook current.
7. Escalate repeated issues into deeper fixes or roadmap work.

## Output format

- support scope
- request categories
- priority rules
- response expectations
- deployment rules
- maintenance log pointers
- escalation path

## Guardrails

- do not blur break/fix support with feature development
- record repeat issues instead of solving them in isolation forever
- keep maintenance changes tied to verification and rollback thinking
- make it clear when a request should become a scoped project instead
