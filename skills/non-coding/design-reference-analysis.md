# Skill: Design Reference Analysis

## Purpose

Use this skill when you need to break a reference design into actionable implementation observations.

## Good use cases

- analyzing screenshots
- competitor-reference breakdowns
- mockup interpretation
- handoff from visual concept to component plan

## Workflow

1. Identify the page or screen purpose.
2. Break down layout hierarchy.
3. Note spacing, density, grouping, and emphasis patterns.
4. Identify reusable component patterns.
5. Identify interaction and state assumptions.
6. Record what is visible vs what is inferred.

## Output format

- screen purpose
- layout observations
- component candidates
- visual hierarchy notes
- interaction assumptions
- uncertainty notes

## Guardrails

- do not present inference as confirmed fact
- separate visual structure from color/style commentary when needed
- focus on reusable patterns, not just surface description
- call out when a reference lacks enough detail for a full implementation
