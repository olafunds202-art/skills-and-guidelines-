# Skill: UI Consistency and Component Mapping

## Purpose

Use this skill when a project needs stronger consistency across related screens or when a design change should become reusable components instead of scattered one-offs.

## Good use cases

- dashboard redesigns
- multi-screen polish work
- repeated form or card patterns
- design-system cleanup
- reducing bespoke UI drift

## Workflow

1. Identify repeated UI patterns.
2. Group them into component families.
3. Define shared states, spacing, and interaction rules.
4. Note where current screens drift from the intended pattern.
5. Define which patterns should be centralized first.
6. Record exceptions intentionally instead of letting them emerge by accident.

## Output format

- component families
- repeated patterns
- consistency issues
- standard states
- centralization priorities
- intentional exceptions

## Guardrails

- do not let every screen invent its own version of the same pattern
- distinguish justified exceptions from accidental inconsistency
- keep shared components aligned with actual usage, not only ideal theory
- reduce drift gradually when a full refactor is too risky
