# Skill: Decision Recording and ADRs

## Purpose

Use this skill when a technical or workflow decision is important enough that future sessions should not rediscover it from scratch.

## Good use cases

- architecture choices
- deployment strategy choices
- framework adoption or rejection
- trade-off decisions with lasting consequences
- client-facing handoff decisions

## Workflow

1. State the decision clearly.
2. Capture the context and constraints.
3. List options considered.
4. Explain the selected option and why it won.
5. Document trade-offs and consequences.
6. Record follow-up actions.
7. Link the decision to the files, systems, or workflows it affects.

## Output format

- decision title
- status
- context
- options considered
- selected option
- rationale
- consequences
- follow-up

## Guardrails

- record the why, not only the result
- include rejected alternatives when they mattered
- note negative consequences honestly
- update or supersede old decisions instead of silently drifting
