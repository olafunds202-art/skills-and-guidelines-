# Skill: Revision and Change Management

## Purpose

Use this skill when client feedback arrives and you need to separate normal revisions from changes that alter scope, architecture, timeline, or responsibility.

## Good use cases

- design/content revisions
- post-demo feedback
- late feature requests
- maintenance-phase change requests
- client projects with iterative signoff

## Workflow

1. Record the requested change exactly.
2. Classify it as:
   - content revision
   - design adjustment
   - functional change
   - net-new scope
3. Identify impact on files, time, integrations, or dependencies.
4. Confirm whether it fits the agreed phase or needs separate approval.
5. Update the work plan and handoff notes if accepted.
6. Track the request through completion.

## Output format

- request summary
- category
- impact
- included or out-of-scope decision
- approval status
- implementation notes
- follow-up

## Guardrails

- do not silently absorb major scope changes
- keep revision history readable
- clarify whether a request changes launch timing
- record client approvals for meaningful scope shifts
