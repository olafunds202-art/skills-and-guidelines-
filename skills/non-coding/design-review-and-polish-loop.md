# Skill: Design Review and Polish Loop

## Purpose

Use this skill when implementation exists and the next job is structured visual review and refinement.

## Good use cases

- UI polish rounds
- screenshot review cycles
- client design feedback
- pre-release styling QA
- layout consistency review

## Workflow

1. Compare the built result to the reference or brief.
2. Separate functional issues from visual issues.
3. Prioritize issues by impact on clarity, usability, and trust.
4. Group polish work into reviewable batches.
5. Re-check after each batch instead of piling on endless changes.
6. Record what differences are intentional.

## Output format

- reference used
- issues found
- priority
- batch plan
- intentional deviations
- remaining polish notes

## Guardrails

- do not collapse all design feedback into one vague list
- distinguish blocking visual issues from nice-to-have refinements
- note when visual review is limited by tooling or environment
- keep the loop finite and outcome-oriented
