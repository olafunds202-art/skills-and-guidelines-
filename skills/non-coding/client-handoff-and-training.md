# Skill: Client Handoff and Training

## Purpose

Use this skill when a project is being delivered to a client and they need clear instructions, boundaries, and next steps.

## Good use cases

- website handoff
- dashboard/admin handoff
- CMS editing handoff
- automation ownership transfer
- project completion summary

## Workflow

1. Summarize what was delivered.
2. List environments, accounts, and access expectations.
3. Explain what the client can edit or operate safely.
4. Document deployment, publishing, or content-update steps.
5. Document known limitations and recommended next improvements.
6. Clarify support or maintenance boundaries.
7. Provide a final handoff checklist.

## Output format

- delivery summary
- access map
- editable areas
- operating instructions
- known limitations
- support boundaries
- next recommendations

## Guardrails

- handoff must be readable by a non-technical stakeholder where possible
- do not leave credentials embedded in docs if avoidable
- distinguish completed delivery from future recommendations
- make the first post-handoff action obvious
