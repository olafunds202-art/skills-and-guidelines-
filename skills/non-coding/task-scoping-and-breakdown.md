# Skill: Task Scoping and Breakdown

## Purpose

Use this skill when a request is too large, fuzzy, or risky to execute as one unit.

## Good use cases

- breaking a project into phases
- turning a feature idea into execution slices
- preparing work for implementation or delegation
- reducing risk before coding starts

## Workflow

1. Restate the request.
2. Identify the smallest meaningful deliverable.
3. Split the work into phases or milestones.
4. Mark dependencies between steps.
5. Flag risky or unclear phases.
6. Define verification for each phase.
7. Identify where confirmation is required before proceeding.

## Output format

- goal
- scope summary
- phases
- dependencies
- risks
- verification checkpoints
- decision points

## Guardrails

- avoid giant one-phase plans
- each phase should be verifiable
- separate discovery from implementation when uncertainty is high
- note where the user must confirm before destructive or major changes
