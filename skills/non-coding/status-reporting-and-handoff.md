# Skill: Status Reporting and Handoff

## Purpose

Use this skill when work needs to be handed to a user, teammate, or future session with minimal confusion.

## Good use cases

- end-of-session summaries
- client progress reports
- developer handoffs
- paused work with next steps
- implementation summaries after a milestone

## Workflow

1. State what was requested.
2. State what was completed.
3. State what remains.
4. State blockers, risks, or unresolved questions.
5. Give clear next steps.
6. Link relevant files, commits, docs, or environments.

## Output format

- request summary
- completed work
- remaining work
- blockers or risks
- verification status
- next actions
- referenced files or links

## Guardrails

- do not blur completed work with planned work
- call out missing verification explicitly
- surface unresolved risk instead of burying it
- make the next step obvious to the receiver
