# Skill: Project Brief and Requirements

## Purpose

Use this skill when the work is still being defined and the main need is to turn an idea into a clear, usable brief.

## Good use cases

- turning a rough idea into a buildable scope
- clarifying goals before implementation starts
- preparing a client project brief
- capturing assumptions before planning and estimation
- reducing ambiguity before coding begins

## Workflow

1. Define the outcome in plain language.
2. Identify the user, customer, or stakeholder.
3. Clarify the problem being solved.
4. List required outcomes and non-goals.
5. Capture constraints, risks, and dependencies.
6. Identify success criteria.
7. Record open questions that still block execution.

## Output format

- summary
- target user or stakeholder
- problem statement
- goals
- non-goals
- scope
- constraints
- assumptions
- dependencies
- success criteria
- open questions

## Guardrails

- separate requirements from assumptions
- do not hide uncertainty behind vague wording
- prefer concrete outcomes over feature lists alone
- identify what is out of scope, not only what is in scope
