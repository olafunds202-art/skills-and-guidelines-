# Skill: Documentation Sync and Knowledge Capture

## Purpose

Use this skill when implementation, investigation, or planning work changes what the team needs to know later.

## Good use cases

- updating docs after feature work
- recording setup or deployment knowledge
- capturing recurring patterns from a session
- reducing repeated explanations across sessions
- aligning docs with current reality

## Workflow

1. Identify what changed.
2. Identify which docs are now stale or missing.
3. Update the smallest useful documentation set first.
4. Capture new patterns, caveats, or commands.
5. Link related decisions, open questions, or follow-up tasks.
6. State what is still undocumented if anything remains.

## Output targets

- README updates
- guides
- setup notes
- project memory files
- decision logs
- handoff notes

## Guardrails

- do not claim docs are current if important gaps remain
- prefer concise useful documentation over long stale prose
- document commands, constraints, and failure modes when they matter
- capture why a workflow exists if it is not obvious
